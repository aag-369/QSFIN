# QSFIN Website — Full-Stack Application

A real frontend + backend, not a static mockup. The FastAPI backend (`backend/main.py`) imports
and calls the actual pipeline modules built earlier in this project (`digital_twin`, `agents`,
`reasoning`, `optimization`, `federated`, `orchestration`) — every endpoint marked "live" in the
UI genuinely re-executes that Python code on each request.

## Run it

From the `qsfin/` project root (one level up from this `webapp/` folder):

```bash
pip install -r requirements.txt
pip install fastapi uvicorn
uvicorn webapp.backend.main:app --port 8420
```

Then open **http://127.0.0.1:8420/** in a browser. The full interactive dashboard from earlier in
the project is served alongside it at **http://127.0.0.1:8420/dashboard**.

## What's actually live vs. what's static

**Static** (fixed facts, don't need a backend call): the India forensic-capacity statistics in the
hero and Problem section, the five-stage pipeline descriptions, the five research-thread cards, the
roadmap, and the About section — these are facts and project documentation, not computed values.

**Live** (genuinely calls the backend on page load or button click):
- Pipeline section stat lines (evidence count, findings count, top scenario) — `GET /api/case`
- The Explainability dossier card — `GET /api/case`, rendered from real `reasoning_layer` output
- "Re-run full case analysis live" button — `POST /api/case/rerun`, recomputes the entire pipeline
- "Re-run optimizer" button — `POST /api/optimization/rerun`, a fresh simulated-annealing pass
  with a new random seed each click, verified against the exact brute-force optimum every time
- "Re-run federated training" widget — `POST /api/federated/rerun?rounds=N`, retrains the 4-agency
  FedAvg simulation from scratch with the number of communication rounds you choose

## API reference

| Method | Path | What it does |
|---|---|---|
| GET | `/api/health` | Backend status check |
| GET | `/api/case` | Full case report (digital twin summary, all findings, reasoning ranking, optimization result, cross-check) |
| POST | `/api/case/rerun` | Recomputes the entire pipeline live |
| GET | `/api/digital-twin` | Render-ready 3D scene JSON |
| GET | `/api/agents/findings` | All agent findings |
| GET | `/api/reasoning` | Scenario ranking with full explanation chains |
| GET | `/api/optimization` | Cached QUBO optimization result |
| POST | `/api/optimization/rerun?seed=N` | Fresh annealing run (seed optional — random if omitted) |
| GET | `/api/federated` | Cached federated learning result (15 rounds) |
| POST | `/api/federated/rerun?rounds=N&local_epochs=N` | Fresh FedAvg training run |
| GET | `/dashboard` | The full interactive dashboard (digital twin viewer, all tabs) |

## A reproducibility bug caught and fixed during testing

While live-testing the federated-learning widget, repeated server restarts produced different
accuracy numbers each time — traced to `federated/fedavg.py` seeding its train/test split with
Python's built-in `hash()` on the agency ID string, which is randomized per-process
(`PYTHONHASHSEED`) by default. Fixed by switching to `zlib.crc32`, which is stable across
processes, platforms, and Python versions. Confirmed via three independent process runs producing
identical output. Worth knowing about if you're citing these numbers in the research paper —
they're reproducible now, but weren't when generated by any run of this module before this fix.

## Before you deploy this anywhere public

- Fill in the three placeholder link fields in `frontend/index.html`'s About section (GitHub,
  LinkedIn, Portfolio — search for `data-placeholder`).
- This runs a single in-process backend with no auth, no rate limiting, and no HTTPS — fine for a
  local demo or a trusted internal network, not fine as-is for a public production deployment.
- All data is synthetic; nothing here should be presented as analysis of a real case.
